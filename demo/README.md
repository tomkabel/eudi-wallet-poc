# Android age-proof demo — recording runbook

Split-screen recording: the Expo UI carries the user experience, a terminal
carries the real prover. Nothing in the UI talks to the verifier — there is no
native bridge — so the two are recorded side by side and the terminal is what
makes the claim checkable.

## Measured, on this machine

Taken from `demo/demo.sh prove adult` on an 8-vCPU host, prover built with
`-C target-cpu=native` (`rust/.cargo/config.toml`):

| Quantity | Value |
|---|---|
| PROVE | 6.1–6.5 s |
| VERIFY | 2.5 s |
| Proof size | ~360 KB (359,988 B) |
| Wall clock, tap to answer | ~16.7 s |

Quote these in overlays, not the `740 ms / 265 ms` in `README.md` and
`zk-age-poc/REPRODUCE.md`. Those are a different binary (`age_demo`, Google's
test mDL vector) on a different host, and an overlay claiming 740 ms beside a
terminal printing 6.3 s discredits the demo it is captioning.

`lib/eudiw/mockData.ts` in the UI submodule is calibrated to these numbers
(0.9 + 6.3 + 2.5 = 9.7 s). Re-measure and re-tune there if the demo moves to
another machine — a stepper that finishes early reads as fake.

## Running it

Terminal A, left of frame:

```bash
demo/demo.sh serve
```

Mints `demo-data/{adult,minor}` on first use, merges both issuers into one trust
store, and binds the verifier to the LAN address the phone can dial. It prints
that URL. Phone and laptop must be on the same network.

Terminal B, right of frame, one per take:

```bash
demo/demo.sh prove adult    # HTTP 200, valid:true
demo/demo.sh prove minor    # HTTP 400, refused on the predicate value
demo/demo.sh prove tamper   # valid:false, proof bound to a different nonce
demo/demo.sh prove replay   # HTTP 410, the nonce is single-use
```

The credential directories survive every run, so a take can be repeated without
re-minting. `EE_PROVER` overrides the prover path, `EE_PORT` the port.

`demo-data/` is gitignored: it holds the holder's device private key. The issuer
key is generated in memory for the run and never written — only its public half
reaches `issuers.json`.

## Honest framing

The UI's proof stepper is a timed animation, not a bridge to the prover. Say so,
or show the terminal as the source of truth and let the UI be the interface.
Claiming the phone generated the proof on screen would be false: the proof in
frame is generated by `ee_poa_demo` on the laptop.
